# Build Sequence

Canonical raw source: `research/jack-portfolio-scrollytelling-research-plan-updated.md`.

## Phase 0: preserve current site

- Keep the current static site intact.
- Do not edit `index.html` or `style.css` during documentation organisation.
- Capture a baseline screenshot before implementation work.

## Phase 1: research and reference lock

- Review the copied research package.
- Confirm target references and scene constraints.
- Decide whether to migrate from plain HTML/CSS or keep a static implementation.

## Phase 2: documentation lock

- Finalise strategy, design, motion and storyboard.
- Fill every scene spec with acceptance criteria.
- Create the initial asset ledger.

## Phase 3: static skeleton

- Implement the new information architecture without heavy motion.
- Keep existing content recoverable.
- Verify desktop and mobile layout.

## Phase 4: vertical prototype

- Build one high-value scene end to end.
- Include reduced-motion and mobile fallbacks.
- Validate performance before adding more scenes.

## Phase 5: remaining scenes

- Add scenes one at a time.
- Each scene must pass visual, accessibility and performance checks.

## Phase 6: deployment

- Verify GitHub Pages output.
- Check links, metadata, mobile layout and reduced motion.
- Update Obsidian pointer and project evidence notes only with links, not duplicate specs.
